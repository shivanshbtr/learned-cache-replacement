# Decision log
1. **Data accesses only.** Instruction fetches are not sent through the caches (lackey I lines only give the PC and instruction count).
2. **L1/L2: LRU, non-inclusive, write-allocate.** Stores are treated like loads. Dirty write-backs from L2 to the LLC are not modelled (report limitation).
3. **Line-crossing accesses** become one LLC-side access per line.
4. **LLC: demand fetch, no bypass.** Belady = MIN without bypass, optimal for this class (checked against exhaustive search on tiny traces).
5. **MPKI uses the fixed instruction count of the trace.** No timing feedback: a policy cannot change how many instructions the program executes, so MPKI ratios equal miss ratios.
6. **Warm-up** = first `warmup_frac` of LLC accesses; state is updated, stats are not.
7. **ROI detection:** lackey does not print stored values, so the first store to `roi_marker` = begin, the second = end. lackey2trace stops reading at ROI end (Valgrind then stops on the closed pipe). Workloads are built `-no-pie` so the marker address from `nm` is fixed.
8. **Compiler barriers** added to ROI_BEGIN/ROI_END in `applications/common.h` so -O2 cannot move memory operations across the marker.
9. **Trace size guard:** `--max-records` in lackey2trace; `check_disk.sh` checks `/` and `/mnt/c` because inside WSL2 `df /` shows the virtual disk size, not the real Windows free space.
10. **Belady ties** (several lines never used again): lowest way index.

Known simplifications: virtual addresses, no prefetcher, no write-back traffic, no timing model, single core.

## Batch B additions
11. **Extra baselines:** BIP (bimodal insertion, 1/32 MRU insertions), BRRIP (RRIP with bimodal insertion), DRRIP (set dueling between SRRIP and BRRIP, 10-bit PSEL, leader sets = set%G==0 for SRRIP and set%G==G/2 for BRRIP with G=min(64, sets)). They use fixed constants (1/32, 10 bits), so they do not change the config hash. Added because SRRIP gets 0% on cyclic thrashing patterns where Random and bimodal policies do well.
12. **conv redesigned** as a multi-output-channel convolution (`conv W K OC seed`): the image is swept once per output channel plus one output plane per sweep, so reuse distance exceeds the LLC when 2*W*W*4 bytes > LLC size.
13. **Reproducible tracing:** workloads run under `env -i` (empty environment) with ASLR off; `scripts/repro_check.sh` traces one run twice and compares md5 of the LLC traces.
14. **Labeler** (`belady/labeler.h`): replays an LLC trace with a driver policy; at each miss in a full set it records the set state and the Belady victim SET (all lines never used again tie). The recorded state has only past information, `next_use` is stored as label information. Drivers: `lru` and `belady` by default (DAgger later: the learned policy as driver). Decisions where every way ties (all lines never reused) have no learning signal and can be dropped (`dataset.informative`).
15. **Stride:** the dataset keeps every STRIDE-th decision (default 2) to bound disk use; warm-up decisions are stored but flagged by `seq < warmup` (use `dataset.measured`).
16. **Capped traces:** matrix and conv inputs use `MAX_RECORDS` (partial ROI).

## Batch D additions
17. **MRU baseline** (`mru`): evicts the most recently used line. Added because the matrix and conv workloads are cyclic sweeps where a pure "evict newest" rule is optimal-like (offline rule match with the Belady victim 0.96 to 0.99 on matrix); a learned model must beat it, not only LRU/SRRIP/DRRIP/BIP.
18. **LSTM + attention is a small PARROT-inspired model** (see docs/models.md for the exact list of differences). It is stateless per decision: the LSTM is run over the last H accesses at every eviction decision (zero initial state), so no hidden state has to be maintained or saved when applications switch.
19. **History ring in the policy:** `LearnedPolicy` (kind LSTM) pushes every LLC access (hit or fill) into a ring indexed by the global access number, so the history is identical to the one the Python feature code rebuilds from the trace (`features.build_hist`); parity is tested decision by decision.
20. **Auxiliary reuse-distance loss** (`--aux`, default 0.1): MSE on log2(1+reuse distance)/21 of every candidate, computed from `next_use` (label information, never an input); the head is dropped at export.
21. **DAgger = relabelling the states the learned policy visits.** The learned policy drives the cache (labeler `--driver mlp:|gbdt:|lstm:`), the Belady label is computed for the visited states, the model retrains on the union with the Belady-driven and LRU-driven data. Only train and val traces are used. States are collected twice: driven by the specialized model and by the generic model, because the generic LightGBM on graph got worse than LRU (distribution shift) and needs states from its own policy.
22. **run_models.sh runs every model file by glob** (`<w>_*.{mlp,gbdt,lstm}` and `all_*.*`) so DAgger and size variants show up without editing the script; `summarize.py` prints one compact block per trace with the gap closed and the gain over the best simple baseline.

## Batch E+F additions
23. **Final model set is chosen by a rule on VALIDATION results only** (`final_plan.py select`): per family (mlp, gbdt, lstm) the variant (base, dag1, dag2) with the highest mean gap closed over the four val traces, specialized and generic models together; ties within 0.001 go to the earlier round. The set is written to `results/final/model_set.json` with SHA-256 of every file and frozen when the test split starts (`test_started`); a re-run does not change it.
24. **E3 equal total storage:** a generic MLP with the same architecture and training data, hidden width chosen so its file size is as close as possible to the sum of the four specialized MLP files (`final_plan.py bighidden`); seeds 2 and 3 of every final MLP retrain on the SAME labeled data (the DAgger data came from the seed-1 models), so mean +- std over 3 seeds measures training noise only.
25. **Multi-application engine** (docs/multi_app.md): round-robin by instructions, owner id in the tag, global time, PCs of other applications hidden from a model; arbitration rules req / own / gen; ownership uses `victimAllowed` (scores computed on the whole set, only allowed ways can win).
26. **Cost model is explicit and swept** (configs/cost_model.json); all activation numbers are model outputs, never measurements.
27. **E5 uses two other LLC sizes and one other associativity with the same traces and the same (not retrained) models**, because L1/L2 filtering does not depend on the LLC; stated as a limitation (models were trained at 2 MB / 16-way).
28. **E6 latency is measured on a prefix of each test trace** (`--max-accesses`, default 600000): latency needs decisions, not the whole trace; miss counts from that run are never reported.

## Extension: LSTM DAgger and mixed-stream DAgger
29. **LSTM DAgger round 1** (`dagger_round.sh 1 lstm`) was run after the main results were frozen. The new LSTM is judged on val like every variant; it gets one test run in the extension section. The frozen model set (base LSTM) is not replaced.
30. **Mixed-stream DAgger** (docs/mixed_dagger.md): DAgger where the visited states come from a SHARED cache (merged streams of train/val inputs, composite driver req=/own=/gen=). Per-application models see only their own PCs (others as 0) and their own requests, as in the simulator. Models go to `models_ext/`, results to `results/ext/`, test run once with a marker file.
31. **Merged-trace encoding:** application id in line bits 48+ and PC bits 56+; checked to fit; the set index uses the plain line so apps compete for sets exactly as in `multisim`.
32. **LSTM `_dag1` extension (val result):** mean gap closed of the specialized LSTMs on the 4 val traces: base 69.5% -> `_dag1` 72.8% (graph 38->43, hash 40->48, matrix/conv 100). Chosen on val; one test run in `scripts/ext_lstm_test.sh` (marker file, refuses a second run). Frozen set unchanged. On hash the `_dag1` LSTM equals the `_dag1` MLP (413,329 vs 413,924 misses): the earlier gap came from the missing DAgger round.
33. **LSTM `_dag1` extension (test, run once, 2 MB 16-way, 8 test traces):** mean gap closed, specialized: LSTM base 68.0%, LSTM `_dag1` 70.6%, MLP `_dag1` 70.6%. Generic: LSTM base 64.0%, LSTM `_dag1` 71.0%, MLP `_dag1` 70.8%. With the same DAgger round the LSTM equals the MLP (differences of at most 0.5% in misses, in both directions); it costs ~5x the storage and ~10x the decision latency (E6). The base-LSTM deficit in E2 was a missing DAgger round, not the architecture. Frozen set unchanged; this is the extension section only.
34. **mix1 result (val):** shared-cache misses of the new models vs the frozen ones, 2 MB: req -22.9%, gen -15.3%, own +3.9% (worse); 8 MB: req -21.1%, gen -27.7% (gen beats the best simple baseline BIP by 6.8%), own +23.3% (worse). Single-application val misses within 1% of the frozen `_dag1` models.
35. **mix1b (expert-driven merged data added):** mix1 recorded the merged streams only with learned drivers; the standard DAgger first step (expert drives the new environment) was missing. mix1b adds LRU- and Belady-driven merged datasets (`mixlru1`, `mixbel1`). mix1 vs mix1b is decided on the val mixture only before the single test run.
36. **mix1 vs mix1b on TEST (run once, both versions, E8 test mixture):** 2 MB: gen mix1b 2,466,003 misses (+6.3% vs DRRIP 2,633,063, gap closed 71.2%), req mix1b 2,542,974 (+3.4% vs DRRIP); frozen gen 3,024,787. 8 MB: gen mix1 697,973 (+8.2% vs BIP 760,486, gap 73.5%), mix1b 779,318 (-2.5%). Val and test agree: mix1b wins at the training size (2 MB), mix1 at 8 MB (not retrained). mix1b is the primary version (chosen on val at 2 MB); both are reported.
37. **Ownership rule stays negative** with every model version (behind the best simple baseline at both sizes). Explanation offered in the report as a hypothesis from the numbers and the E8 eviction matrices (near static partitioning, 0-2% cross-application evictions, equal shares are not efficient shares), not as a tested result.
38. **Extension to all families and round 2:** mixed-stream DAgger for LightGBM and the LSTM (same datasets/drivers; LSTM drivers = the `_dag1` LSTMs; history features use plain lines on merged streams, tested) and a second round (`mix2`, driven by the mix1b models) for all three families. Chain: `scripts/mixed_all.sh`.
39. **Test protocol for these candidates:** the first test mixture (E8) was used for MLP mix1/mix1b. New candidates are evaluated once on a second test mixture (`TESTSET=2`, marker `test2_started`) together with the MLP versions; choices are made on val only, everything is reported.
40. **Out-of-memory fix (generic round-2 models):** the first mixed_all run was OOM-killed (11.6 GB) in the three generic round-2 trainings (MLP, LightGBM, LSTM): loading ~4M rows and the one-shot `(num-mean)/std` plus `.std()` made several full-size temporaries. The trainers now compute mean/std in chunks (float64) and normalize in place; LightGBM frees the raw arrays after building its matrices. Same arithmetic and protocol (identical normalized values; mean/std slightly more accurate). The four specialized round-2 models of each family were trained before the fix and are unchanged; only the generic ones are trained with the new code.
41. **Second memory fix (vocabulary):** the real peak was `vocab_from_files`, which loaded all ~72 dataset files at once (every array) just to count PCs. It now streams the files and reads only `trace_pc` (plus `trace_line`/`seq` for merged files); the resulting vocabulary is identical (checked against the old function for all workload views). `load_rows` also frees the per-file pieces while joining them.
